# GuardAI-Lint 🛡️

**GuardAI-Lint** — это консольный инструмент автоматического сканирования конфигураций ИИ-агентов (LLM) на соответствие стандартам безопасности и корпоративного комплаенса (**Policy-as-Code**). 

Проект вдохновлен концепцией декларативной проверки политик (как в движках *Open Policy Agent / OPA* и *Kyverno*) и разработан как полезная утилита для предотвращения критических уязвимостей в ИИ-системах до их отправки в продакшен.

---

## 💡 Какую проблему решает проект?
При интеграции больших языковых моделей (например, ChatGPT) в бизнес-процессы разработчики сохраняют системные инструкции и параметры ИИ в конфигурационных файлах. Ошибки или невнимательность при их заполнении могут привести к:
1. **Prompt Injection** — взлом и перехват управления ИИ-ботом со стороны обычного пользователя.
2. **Prompt Leakage** — утечка внутренних коммерческих инструкций, алгоритмов и секретов компании через диалоговое окно.
3. **Галлюцинациям модели** — из-за завышенных параметров случайности (`temperature`), что заставляет робота техподдержки путать цены, выдумывать скидки или вести себя неадекватно.

**GuardAI-Lint** автоматически сканирует файлы настроек, проверяет их по жесткому набору правил и на месте блокирует деплой небезопасного кода.

---

## 🛠️ Архитектура и стек технологий
* **Ядро политик безопасности:** Логика и концепция декларативного языка правил **Rego** (документ со сводом правил находится в `/policies/safety.rego`).
* **Движок автоматизации:** Скрипт парсинга и валидации на **Python 3**.
* **Интерфейс визуализации:** Генератор интерактивных **HTML-отчетов комплаенса** (упрощенный аналог плагинов для платформ управления разработкой вроде *Backstage* от Spotify).
* **Интеграция с CI/CD пайплайнами:** Поддержка системных кодов возврата (**Exit Codes 0/1**) для автоматической блокировки сборки проекта на удаленных серверах (GitHub Actions, GitLab CI).

## 🚀 Быстрый старт

### 1. Структура проекта
Убедитесь, что файлы на вашем компьютере расположены в следующем порядке:
```text
guardai-lint/
├── policies/
│   └── safety.rego           # Декларативные правила безопасности
├── ai_config.json            # Файл конфигурации ИИ-агента
├── lint.py                   # Главный скрипт сканирования
└── README.md                 # Документация проекта
```

### 2. Пример проверяемого файла (`ai_config.json`)
```json
{
  "agent_name": "SupportBot-v1",
  "model": "gpt-4o",
  "temperature": 0.95,
  "system_prompt": "Ты — помощник поддержки. Отвечай на вопросы пользователей."
}
```

### 3. Запуск линтера
Запустите сканирование через ваш терминал:
```bash
python3 lint.py
```

### 4. Просмотр результатов
* В консоли отобразится текстовый вердикт безопасности.
* В корне папки автоматически сгенерируется или обновится файл `compliance_report.html`. Откройте его двойным кликом в любом браузере, чтобы увидеть наглядный графический отчет по каждому правилу безопасности.

## 🤖 Режим автоматизации (CI/CD Конвейер)
Инструмент спроектирован так, чтобы его можно было встроить в процесс автоматического тестирования при каждом `git push`. Скрипт сообщает серверу о результатах проверки с помощью стандартных кодов выхода:
* **`Exit Code 0` (SUCCESS):** Проверка пройдена успешно. Файл безопасен, уязвимостей нет. Робот CI/CD продолжает деплой на живые сервера.
* **`Exit Code 1` (FAIL):** Обнаружены критические уязвимости (высокая температура или незащищенный промт). Пайплайн сборки принудительно останавливается, разработчик получает отказ.
* **`Exit Code 2` (ERROR):** Ошибка окружения (файл конфигурации не найден в директории).

Проверить код возврата в терминале локально можно командами:
* **Windows (cmd):** `echo %errorlevel%`
* **Linux / macOS:** `echo $?`
